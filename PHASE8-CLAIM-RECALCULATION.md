# Phase 8 — Claim recalculation consistency

## Change

`js/compute-patient.js` now tags deduction-reason entries created during a calculation with `_generatedByCompute: true`. At the start of the next calculation, `resetComputedDeductionReasons()` removes those generated entries (as well as legacy `auto`/`rule` entries) while retaining reviewer-entered manual reasons that were not generated by the calculation.

This addresses an accumulation case: manual override reductions and manual cap/copay outputs were marked `source: 'manual'`, so the previous cleanup retained them and another recalculation appended duplicates.

## Regression coverage

`tests/tests.js` now checks that recalculation cleanup removes generated automatic, rule-based, and generated-manual entries while retaining a reviewer-entered manual reason.

## Validation performed

- `node --check` passed for all JavaScript files.
- All JSON files parsed successfully.
- A headless Chromium attempt against `tests/test-runner.html` exceeded the 25-second execution limit; the browser test suite therefore remains **not confirmed as executed**.

## Compatibility note

Previously persisted manual deduction entries created by older versions do not carry `_generatedByCompute`. They cannot be reliably distinguished from genuine reviewer-entered manual reasons, so this change intentionally does not delete them. A one-time cleanup of historical duplicates requires a reviewed migration rule and should not be guessed.
